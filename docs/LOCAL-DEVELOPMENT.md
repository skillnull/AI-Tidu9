# 本地开发

[README](../README.md) · [English](./LOCAL-DEVELOPMENT.EN.md) · [贡献指南](./CONTRIBUTING.md)

本文档只描述仓库本地开发，不包含服务器或远程部署步骤。远程使用由[远程部署文档](./REMOTE-DEPLOYMENT.md)独立维护。

## 启动开发环境

需要 Node.js 22.14 或更高版本：

```bash
npm run tidu:setup
```

`tidu:setup` 安装依赖、构建 CLI，并自动启动个人版前端与接口服务。`tidu:dev-p` 启动前端和内置开发控制能力（`9639`），`tidu:dev-api-p` 独立启动接口（`9640`）。CLI 是命令入口，不作为单独服务启动或展示。企业版本地开发使用对应的 `-e` 命令和 `9739`、`9740` 端口。

开发数据保存在 `.tidu-dev/tidu.sqlite`，与全局安装版数据隔离。前端源码由 Vite 热更新；后端 TypeScript 修改后通过页面或命令重启独立接口服务。

配置、连接修复和模式切换统一从前端地址操作。开发代理核验本地页面的同源来源后，将来源和 Host 转为目标服务地址，兼容前后端独立端口；外站和不匹配来源仍会被拒绝，后端同源写入保护保持生效。

## 本地 Codex 配置验收

配置页为唯一的九门上游模型选择入口。宿主模型、公司 Provider 模型和自定义模型三者互斥；模型列表跟随所选上游来源切换：

- **九门**：Codex 只显示“九门赛博提督”；配置页决定 Agent 内核实际使用的宿主、公司或自定义上游。
- **官方直连**：精确恢复安装前配置，Codex 模型列表只显示官方模型，调用不经过九门运行时。

九门自有备份目录只保留首次安装基线与最新回滚点；不会删除来源不明的 Codex 配置备份。

模式切换同时同步 Provider、模型和官方 `thread/settings/updated` 通知；已打开的空闲对话自动更新模型，运行中的轮次在结束后同步。下一轮携带的旧模型选择不会覆盖当前模式。

重试沿用官方机制：断流由原生客户端重连，真实容量错误保留 `server_is_overloaded` 分类，触发客户端已有倒计时和点击重试。协议与配置错误不伪装成容量错误，不增加旁路重试队列或修改官方安装包。跨模式请求用公开消息、摘要和工具结果重放，并清空旧 Provider 的 `previous_response_id`；不改写官方聊天记录。

stdio 消息大小按官方 Codex `0.166.0-alpha.5.1` 的[传输实现](https://github.com/openai/codex/blob/f79b26ccbb3116b052544666a181012fb45dc49b/codex-rs/app-server-transport/src/transport/stdio.rs)对齐：JSON 按行读取、序列化后追加换行，默认不额外设置固定消息字节上限。共享客户端只有显式传入 `maximumMessageBytes` 时才检查该限制；Codex 适配器不覆盖默认值。此处是 stdio 消息帧语义，HTTP 请求体、MCP 服务和业务安全门禁的限制仍各自生效。

额度仍位于“模型统计”，客户端卡片不增加跳转按钮。九门接入保留 Codex 原生账号、额度和用量查询，由官方进程返回数据；本页也独立读取余量、重置时间和可用重置次数。统计查询不为未激活的宿主启动模型会话。当共享模型缓存来自更新的 Codex 版本时，自动发现优先选用已安装且与缓存对应版本的 CLI，避免旧版解析失败；显式命令覆盖保持最高优先级。账号和额度并行读取，查询超时仍保留已取得的数据。九门轮次的空额度通知会触发独立的官方数据刷新，不覆盖已有官方余量，也不阻塞轮次终态。每日用量接口失败不会清空已取得的额度，未返回的字段明确标为未提供。强度选项按原生 `reasoningEffort` 字段返回。

服务页只显示 `tidu:dev-p` 与 `tidu:dev-api-p`。每项都来自对应的真实进程，具有独立 PID、端口、状态、启动命令、日志位置、配置位置和代理配置，以及启动、停止、重启操作。开发日志实时输出到各服务的启动终端；未使用 Nginx 的服务明确显示“未配置”。安装或远程运行时也只展示实际运行单元；个人安装版不暴露企业命令，企业安装版不暴露个人命令。CLI 可执行 `tidu service status` 或 `tidu service <start|stop|restart> <service-id|all>`。

`tidu:dev-p` 启动前会检查安装版运行锁和默认端口。检测到安装版冲突时停止启动，并提示先执行 `tidu service stop all && tidu uninstall --confirm DELETE`，不会自动删除数据。

切到九门前，本地运行时必须可访问并通过最小推理验证；验证失败时保持或恢复官方配置，并显示具体错误。正常停止本地开发服务时，如果九门配置正在生效，也要恢复官方配置。

## 验证与停止

```bash
npm run check
```

开发或测试结束后，在运行 `tidu:setup` 的终端按 `Ctrl+C` 可停止由它启动的前端与接口进程；单独启动的接口服务则在其终端停止。确认对应 PID 与端口已经退出，不把测试服务留在后台。

本地功能变更若同时影响服务器部署，只同步更新独立的远程部署文档；不要把远程操作写入本地开发流程。
