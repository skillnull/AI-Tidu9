# 架构基线

[English](./architecture.en.md)

九门赛博提督采用“模块化单体优先、适配器边界稳定、按规模渐进拆分”的架构。个人用户只需一个轻量进程；团队和企业可在后续阶段按负载拆分网关、调度器与 Worker，而无需改写核心协议。

## 当前模块

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| `packages/tidu/src/cli` | `tidu` 命令入口 | 只负责交互和进程退出码，不承载领域逻辑 |
| `packages/tidu/src/core` | 产品元数据、共享错误和核心领域基础 | 不依赖客户端、模型供应商或存储实现 |
| `packages/tidu/src/config` | 版本化配置契约和安全默认值 | 普通模式与专家模式必须保持配置隔离 |
| `packages/tidu/src/accounts` | 宿主账号桥、多账号Profile与任务账号快照 | 只接收非敏感元数据和委托执行能力，不读取或复制宿主Token |
| `packages/tidu/src/clients` | 本机客户端发现与事务化接入适配器 | 不读取账号或凭据；只写九门专属文件并提供快照、验证与回滚 |
| `packages/tidu/src/protocol` | Agent任务和事件的规范化协议 | 通过显式版本演进，避免绑定具体模型 |
| `packages/tidu/src/agent` | 目标理解、动态规划、有界执行、人工确认、恢复与结果验证 | 模型负责理解与规划，内核负责校验、预算、状态和证据边界 |
| `packages/tidu/src/capabilities` | Agent、Skill、MCP、工具和知识的统一能力注册与按需装配 | 只保存非敏感元数据，按能力、成本和隐私边界选择有界最小集合 |
| `packages/tidu/src/ecosystem` | Capability Provider协议、SDK、能力目录、发现、信任与隔离边界 | 不可信扩展没有合规外部沙箱时失败关闭；发现阶段绝不执行扩展 |
| `packages/tidu/src/qualification` | 集成发布候选的证据分级与门禁判定 | 自动化结果不能冒充长期试用、团队试点或本地材料人工评审 |
| `packages/tidu/src/runtime` | 轻量本地HTTP运行时、虚拟模型与配置中心入口 | 默认仅监听回环地址，只协调适配器，不包含供应商实现或业务编排 |
| `packages/tidu/src/config-center` | 本地配置中心引导数据契约 | 对外提供生效配置与隔离草稿的状态，不直接操作数据库 |
| `packages/tidu/src/openai` | OpenAI兼容虚拟模型、错误与请求校验契约 | 不绑定供应商，不记录请求内容，不伪造推理结果 |
| `packages/tidu/src/providers` | OpenAI兼容与Ollama真实供应商适配器 | 只处理协议转换与调用；不持久化密钥、会话或业务配置 |
| `packages/tidu/src/routing` | 动态模型评分、能力补全、额度回退和主/专家模型协作 | 专家池必须显式启用且调用数有界；路由价格是估算，不替代供应商账单 |
| `packages/tidu/src/security` | 模型与工具出口的运行时Secret Gate | 真实值仅保存在隔离的短期内存作用域，外部出口只接收占位符 |
| `packages/tidu/src/scaling` | 生产任务准入、公平调度、Worker租约、检查点恢复与伸缩观测 | 网关无状态；任务状态通过可替换存储持久化；Worker不直接拥有全局调度状态 |
| `packages/tidu/src/storage` | 存储适配器与九门自身元数据持久化 | Schema与SQL迁移保持语言无关；任务只保存有界胶囊，不保存完整会话 |
| `packages/tidu/src/usage` | 官方、宿主和估算用量的统一观测契约 | 供应商官方用量优先，估算值永远明确标记，不能伪装成官方额度 |

上述模块统一属于公开包 `@skillnull/tidu`。内部目录用于保持代码边界，不形成独立npm包；只有出现独立使用者、版本与发布周期后，才提取新的公开包。

## 设计约束

- 客户端、模型、Agent、Skill、MCP、工具、知识库和存储均通过后续适配器接入。
- SQLite契约由npm包公开的 `storage/contract.json` 与顺序SQL迁移定义，不能绑定Node或Python实现。
- Node主运行时执行同一存储契约；Python SDK通过平台API访问，未来独立Python运行时可使用标准库 `sqlite3` 实现适配器。
- 同一个SQLite数据库只允许一个运行时拥有写入权，跨语言Agent与Worker不得绕过平台API直接争用数据库。
- 核心只表达目标、能力、策略、任务、事件和可验证结果，不把领域识别硬编码进平台。
- 个人部署默认保持低资源占用；PostgreSQL、Redis、队列及分布式 Worker 均为按需能力。
- 所有模型与工具出口必须经过同一强制策略边界，不能由插件或专家配置绕过。
- 配置与协议均带版本号；破坏性变更必须提供迁移和回滚说明。
- 普通草稿、专家草稿与生效快照是三个独立状态；保存草稿不等于启用，写入使用修订号避免并发覆盖。

## 任务与事件契约

独立Agent内核使用版本化任务聚合与追加式事件流。任务只表达稳定身份、目标、验收条件、生命周期状态、修订号和时间；事件使用任务内单调递增序号记录已发生事实，并标注非敏感来源。客户端、规划器、Worker、工具与人工确认共享同一事件包络，不能用供应商私有消息作为核心状态。

Agent内核把模型或专家适配器用于目标理解、计划与重规划，把执行边界留在确定性内核：计划必须通过依赖、工具与输入大小校验；每个任务有步骤、工具调用、事件、证据、重规划次数和总时长硬预算；写入或外部工具默认需要人工确认；非幂等工具在结果不确定的中断后不得自动重放。验收器必须逐条返回合法验收条件和已有证据引用，否则任务不能进入完成状态。

SQLite只持久化恢复所需的轻量任务胶囊：目标、计划、检查点、有界步骤摘要、最小证据包、预算使用量和最终结果。单胶囊限制为256 KB，单步骤计划输入限制为16 KB，摘要限制为2048字符；完整对话、原始模型响应和大块工具输出不进入该存储。凭据、Token与密码仍禁止进入任务、计划或事件。

## 生产伸缩基线

Stage 7 将任务入口拆为无状态 Gateway、单一逻辑 Scheduler 和可水平扩展 Worker。Gateway 只提交和查询任务；Scheduler 统一执行租户安全的幂等准入、全局与租户背压、公平调度、资源组匹配、租约和检查点恢复；Worker 通过注册、心跳、领取、完成或失败协议工作。生产任务状态使用 PostgreSQL 的修订号比较并交换持久化，Worker 注册会在 Scheduler 重启后重新建立。个人部署仍可使用内存实现，不被迫安装分布式基础设施。

每个任务具有载荷、内存和临时空间硬上限，大文件与工具输出通过有界分块流传递。供应商调用支持熔断、冷却与候选回退；滚动升级先排空旧 Worker，失败时恢复原版本。默认观测只暴露计数器、容量、Worker数量和采样后的非内容诊断，不保存提示词、凭据或工具正文。运行时健康接口在队列接近上限或有积压但没有可用 Worker 时给出告警。

自动化基线覆盖10租户、10个并行Worker和1,000个并发任务的无丢失完成，并注入租约超时、Worker消失、检查点重试、供应商失败和滚动升级回滚。该测试用于防止功能回归，不构成吞吐量SLA；正式容量结论必须在目标硬件、数据库和网络环境中重新压测。

## 开放能力生态

能力注册表负责按任务装配能力资产，Capability Provider Protocol 负责扩展的发现、信任、权限、调用和生命周期边界。模型、Agent、客户端、存储与历史适配器共享同一版本化Manifest；企业私有、本地和官方目录只提供元数据，启用前统一完成协议、完整性、签名、依赖与权限检查。

可信Provider可在有界运行时内调用；不可信Provider必须交给返回隔离证明的外部沙箱。没有沙箱时失败关闭，控制平面不把Node `vm`或普通Worker误称为安全隔离。第三方Agent只能在明确的轮次、工具调用、时间、输出和租户边界内委派。TypeScript SDK是主npm包的稳定子路径，Python SDK仅调用平台API，两者遵守同一协议迁移策略。

## 当前限制

当前主运行时需要Node.js 22.14或更高版本。个人版默认启动仅监听 `127.0.0.1` 的轻量运行时、SQLite和React + Vite配置中心。设置 `TIDU_POSTGRES_URL` 后，同一运行时会附加PostgreSQL企业控制平面和持久化生产任务队列。Docker单机配置默认仍只映射服务器回环地址；跨设备访问必须增加HTTPS反向代理与企业身份认证。当前实现支持无状态Gateway与水平Worker，但Scheduler仍是单一逻辑写入者；Scheduler高可用、领导者选举、跨主机真实容量验证、生产沙箱适配器和真实小团队试点仍未完成。

## 一次安装，多入口连接器

“一次安装”表示设备上只存在一个九门核心、一个配置中心和一份生效策略。安装器负责发现宿主并部署薄连接器；不是用一个最低公分母协议替代所有客户端能力。

| 使用入口 | 首选连接器 | 当前账户与能力来源 | 安装目标 |
| --- | --- | --- | --- |
| Codex应用、CLI与IDE扩展 | Codex Plugin/MCP + app-server | Codex官方会话、模型、工具、权限与共享MCP配置 | `tidu setup`检测后配置一次，所有Codex入口共享 |
| Cursor桌面端 | 用户级MCP + 可移植Agent Plugin | Cursor桌面Agent继续持有当前账户与原生能力 | `tidu setup`只写入九门拥有的MCP项，不复制凭据 |
| Cursor CLI | ACP | Cursor Agent CLI账户、模式、工具、权限、会话与MCP | 安装器验证ACP和独立CLI授权状态 |
| JetBrains、Neovim、Zed等编辑器 | Agent Plugin/MCP或编辑器官方ACP入口 | 被选择的宿主账户与能力 | 加载随包清单；未验证的宿主能力不展示为可用 |
| 浏览器入口 | 九门配置中心或公司网关 | 九门运行时与统一策略 | 个人版直接打开配置中心；跨设备访问要求HTTPS反向代理 |
| 通用OpenAI客户端 | OpenAI兼容虚拟模型 | 九门模型池与Agent内核 | 自动生成Base URL、虚拟模型名和非敏感连接信息 |
| Ollama及其他模型服务 | 供应商适配器 | 上游模型能力 | 由九门调用，不作为用户入口重复安装 |

统一安装器必须是可重复执行的事务：先探测、再展示影响、经确认后安装，随后逐入口握手和真实任务验证；任一连接器失败只回滚自身，不破坏其他宿主。个人版使用当前用户范围，公司版通过MDM、软件分发、团队Marketplace或网关策略完成免人工部署。卸载时删除九门拥有的连接器和注册项，但不删除宿主账户、历史、第三方插件或用户配置。

### 原生全能力接入门禁

- 凭据始终由宿主保管；九门只启动官方委托进程，并清除可能覆盖当前登录的API Key环境变量。
- 必须通过协议握手和真实任务验收确认模式、工具、权限、会话、取消及MCP能力；未通过的能力不得展示为可用。
- 权限请求必须原样返回宿主或用户，不能静默自动批准；`force`、`yolo`、自动批准MCP等危险参数不进入默认启动参数。
- 委托命令与参数由受控适配器生成，配置和模型输出都不能注入可执行文件或启动参数。
- 协议消息需要大小、超时、并发、取消和异常退出边界；默认审计只记录状态与计量元数据，不记录提示词、工具参数、会话正文或凭据。
- 宿主原生能力与公司强制策略必须同时成立。任一策略无法覆盖的通道都应拒绝接入，不能通过兼容模式绕开。

官方“Sign in with ChatGPT”要求独立应用完成OIDC + PKCE授权、用户同意、Profile隔离、Token续期和安全存储，且不会授权读取ChatGPT会话。九门作为独立应用时仍遵循该流程；作为Codex本机扩展时，则通过官方Codex进程复用现有登录，不解析或复制其私有凭据。当前已实现动态注册与已有账号授权请求、Callback校验、无Client Secret换码、受信OpenID发现、RS256身份令牌验证和套餐权限检查；宿主账号桥提供不暴露Token的委托边界。九门自有的浏览器引导、安全持久化、刷新/撤销以及真实账号验收完成前，独立登录项仍不标记为完整。

## 部署与管理边界

| 方式 | 服务端 | 员工本地 | 适用场景 |
| --- | --- | --- | --- |
| 个人本地版 | 不需要 | 安装一个 `tidu` 进程 | 个人模型、Skill、MCP、知识与本地文件协作 |
| 公司集中版 | 公司部署统一网关 | 标准OpenAI兼容客户端无需安装九门 | 模型统一采购、额度、组织策略和纯服务端能力 |
| 公司混合版 | 公司部署统一网关 | 安装轻量连接器 | 需要本地文件、IDE、宿主账号、本地Skill/MCP或数据出端前脱敏 |

管理页面不是唯一控制通道。正式企业部署需要在HTTPS与身份认证后提供管理页面，同时提供等价CLI、版本化配置文件和管理API。页面故障不能影响已启用配置和模型网关运行。强制门禁由服务端出口策略、身份权限、网络出口限制和设备策略共同保证，不能只依靠员工主动安装本地程序。

配置中心内置与当前版本一致的使用指南。个人版说明真实可用的启动、配置和排障步骤。公司版根据已发布的域名、身份认证、虚拟模型、客户端、连接器策略和支持信息生成管理员指南与员工接入页；不得显示供应商密钥。配置发布后自动生成新文档版本，旧版本保留审计记录并标记失效范围。

## 安装生命周期

个人版卸载区分程序、运行数据和用户资产。`tidu uninstall` 在确认运行时已经停止后，将九门自有数据目录原子移动为带时间戳的本地快照；`tidu restore` 只在当前数据目录不存在时恢复最近快照，不覆盖新数据。永久清除会展示精确路径并要求完整确认词，同时只匹配九门数据目录与快照命名空间。自定义数据库路径始终保留。通过 `npx` 临时运行时无需卸载npm包，固定安装则由原包管理器移除。

个人版转公司版不是覆盖安装。引导流程先验证公司地址、服务版本、身份方式、策略边界和客户端兼容性，再创建加密本地迁移快照并展示影响清单。确认后新增隔离的公司Profile并分阶段启用；个人Profile继续保留，公司强制策略只在其声明的组织作用域内生效。任一步失败都回滚到个人Profile，退出组织后也能恢复原个人环境。个人密钥、私有Skill、MCP配置、知识和历史不会因加入公司而自动上传。

### 公司管理员访问密钥

- 公司初始化完成后生成高强度管理员访问密钥，并仅在安装终端和确认页面展示一次。安装人员必须确认已经离线保存，系统不得通过日志、历史页面或普通API再次返回原始值。
- 数据库保存密钥标识、独立盐值、不可逆校验值、算法版本、状态和创建/轮换时间，不保存可读取的原始密钥。
- 每个新管理会话先在HTTPS页面输入密钥。服务端采用恒定时间校验、失败限速和安全审计，成功后只签发短期、HttpOnly、Secure、SameSite会话。
- 管理员重新验证后可以轮换密钥。新密钥仍只展示一次；确认保存后旧密钥立即失效，所有旧管理会话可按策略同时撤销。
- 密钥丢失时不能从数据库找回明文，只能由服务器本机授权运维命令重置，并生成不可删除的安全审计事件。企业SSO和角色权限用于识别具体管理员，不能替代这道部署级密钥门禁。

## 个人体验安全边界

- 普通与专家模式拥有独立草稿；界面切换不改变运行配置。启用前必须通过校验和影响模拟，启用事务保留上一健康版本，探针失败后自动回滚。
- 完整会话可由宿主保留，或使用有容量与时间上限的本地可移植模式；无痕模式不保留会话。九门服务端只维护自身任务胶囊，不复制宿主历史。
